# MiniSplit

## IR / Device B command paths
- IR frames go out from two tasks: `command_task` (direct HA-triggered writes — power, setpoint, mode, Fresh Air — with dedup against fresh Tuya status) and `sync_task`'s 3-minute poll, which sends the Follow-Me heartbeat from the status it just polled (2026-10-06, firmware 1.3.0 — the old separate heartbeat task rebuilt frames from the previous poll's cached status, which put back the pre-correction setpoint after every correction and reverted remote changes before they could be adopted; a heartbeat must only ever carry what the unit holds now), and reconciles the setpoint against Tuya's `temp_set_f` (`setpoint_reconcile_decide()`, 2026-10-05, firmware 1.2.0): exact match; a missed update (unit kept its old value) is resent, a remote/app change (unit moved to a value the bridge didn't send, outside a mode change, held two polls) is adopted into Desired — HA then treats it as a manual override until the next 07:00/19:00 and, since 2026-10-04, reconciles mode (`reconcile_system_mode()` — Desired adopts an out-of-band change from the remote/app, otherwise Desired's mode is resent; see the comment above `MODE_MISMATCH_POLLS`).
- Every IR frame is a full state. Health, swing, eco, turbo, quiet, remote timers, and fan levels beyond IR's 4 are NOT preserved — by design (owner's call 2026-10-04; several bits unconfirmed); see `IR_PROTOCOL_REFERENCE.md`'s "Fields not preserved" table before changing that. Follow-Me IS preserved: command frames carry its bits while it's active (2026-10-04), since a plain frame is the remote's Follow-Me-off frame.
- To check Follow-Me is engaged, compare "Indoor Temp (from Tuya)" (`sensor.mini_split_ac_bridge_temperature_1`) with the Follow-Me sensor: the unit reports the Follow-Me value (within ~1°F, whole-°C steps) when it's on, and its warm onboard reading (~75-77°F) when it's off. See `IR_PROTOCOL_REFERENCE.md`'s "Follow Me behavior".
- Every full-state frame sets Power On unless told otherwise, and with the unit off its mode byte falls back to Auto. So nothing except an explicit power/mode command may send a frame while the unit is off — the Follow-Me heartbeat and setpoint correction were doing exactly that until 2026-10-04 (unit turning itself back on in Auto). Keep that guard on any new IR send path.
- Two ESP32-C6 boards share this PC's USB ports and the same VID/PID: this bridge (MAC `58:8c:81:5d:89:04`) and `../ThreadRouter` (MAC `…5d:89:1c`). COM numbers move. Before flashing, confirm the MAC (`esptool chip_id`/`read_flash` prints it) — on 2026-10-04 the router was overwritten with this firmware by trusting the COM port.
- Fresh Air's IR encoding is resolved (2026-09-10, see `IR_PROTOCOL_REFERENCE.md`'s "Known gaps") — `state[12]` bit `0x01` of the **Type 2** companion frame (not Type 1, which is why earlier attempts missed it, and not detectable from ms-resolution raw-pin captures, which is why the "byte-identical at every level checked" conclusion in the previous version of this note was itself wrong — see `feedback-no-unverified-dead-ends` memory). Wired into `transmit_ir_state_frame()` via `effective_fresh_air()`. Since 2026-10-04 it's also its own HA control: Matter endpoint 11 (On/Off Plug-in Unit), `switch.minisplit_fresh_air`, flashed 2026-10-04. **Confirmed on the real unit 2026-10-05** — `switch.turn_on` at 10:54 turned Fresh Air on (seen in the Tuya app). The switch used to snap back to off for ~5 min after the command; fixed (command recorded before the pre-send refresh) and flashed 2026-10-05.
- Setpoint half degrees are `state[12]` bit `0x04` on this unit, not IRremoteESP8266's `0x20` (2026-10-05, from the remote's own captures + raw Tuya `temp_set`). Before that fix every whole-degree setpoint landed 1°F high (70→71). To check what the unit really holds, read Tuya's raw `temp_set` (°C×100), not just `temp_set_f`.
- Firmware version: `version.txt` + git commit (`CMakeLists.txt`), reported over Matter as the software version and logged at boot. Bump `version.txt` on behavior changes.

## Home Assistant / Climate Rules
- The Sonoff (SNZB-02P) Zigbee temp/humidity sensor is the source of truth for room temperature (relayed into firmware via HA for Follow-Me — see PLAN.md Milestone 3). Apply calibration offsets to the sensor reading, never to the setpoint. The BME280 mentioned in older commits/docs was removed 2026-09-07 — it was never actually wired to the board.
- Do not add smoothing/filtering to Tuya-reported temperature; treat Tuya as a command sink only.
- After changing climate automations, verify by counting setpoint reversals over a comparable window and report before/after numbers.

## Deploying config changes to the live box
- Use `../Wyse5070DebSetup/homeassistant-config/deploy.sh` (2026-10-05): drift check against the last deploy, backup, config check with rollback, then reload (needs `HA_TOKEN` in `/mnt/data/appdata/homeassistant/.env`) or `--restart`. For `.storage` edits (areas, labels, dashboard, seeding, orphans) use `patch-storage.sh <patch.py>`, which always restarts HA even if the patch fails. The manual steps below are what these scripts automate.
- Template entity IDs come from the slugified name: "Follow-Me" becomes `follow_me` -- check the registered ID before referencing a new entity.
- `/mnt/data/appdata/homeassistant/config` on `wyse` (bind-mounted into the `homeassistant` container as `/config`) is NOT a git checkout — there is no `git pull` path to sync it.
- Before overwriting a file there, diff it against the live copy first (`docker exec homeassistant cat /config/<file>` vs the repo version). The live file can have uncommitted edits of its own; overwriting blind can silently clobber them.
- Deploy by `scp`-ing the file to the host, then `docker cp` into the container (e.g. `docker cp /tmp/configuration.yaml homeassistant:/config/configuration.yaml`).
- Sanity-check the YAML parses before reloading/restarting.
